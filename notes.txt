How a Selenium Command Travels to the Browser ?**

Selenium Java library converts your method call into a WebDriver command.

Internally it creates a JSON request.

Selenium 4 uses the W3C WebDriver Standard.

The client sends an HTTP request to the browser driver. Eg( ChromeDriver -> Chrome)

ChromeDriver receives the request and translates the command into instructions Chrome understands.

Chrome searches DOM and finds the element.

Browser returns the unique element ID.

CSS vs XPATH selectors ?

CSS selectors are generally faster and more readable, while XPath is more powerful and supports traversing the DOM in multiple directions using axes.

Axes allow navigation relative to another element.

Absolute XPath depends on the exact DOM hierarchy and breaks whenever developers change the page structure. Relative XPath is more stable because it identifies elements using attributes, text, or relationships rather than fixed positions.

WAITS IN SELENIUM

Implicit wait tells Selenium:

"Keep trying to find an element for up to X seconds before throwing NoSuchElementException."

Characteristics
✅ Global
✅ Applied to all findElement()
✅ Set once
❌ Cannot wait for conditions like clickable/visible
❌ Hard to control

Explicit wait waits for a specific condition to become true before proceeding.

Fluent Wait is an advanced Explicit Wait
Allows:
Custom polling interval
Ignoring exceptions

Why Mixing Implicit and Explicit Waits Causes Problems?
Explicit wait repeatedly calls findElement(), and if an implicit wait is also configured, each poll may wait for the implicit timeout. This leads to compounded and unpredictable wait durations.
Why Thread.sleep() Is NOT a Wait?
Why Hate Thread.sleep()

❌ Slower execution
❌ Increases suite runtime
❌ Flaky tests
❌ Doesn't handle dynamic applications
❌ Not intelligent

Acceptable: Temporary workaround
Not inside production frameworks.

TestNG (Test Next Generation) is a Java testing framework used to organize, execute, and report tests.

Selenium = Interacts with Browser
TestNG   = Controls Test Execution

Key Features :
annotations -> control execution flow
Test Priorities
Grouping Tests
Run same test with multiple datasets.
Assertions
Parallel Execution
Listeners

TestNG is a Java testing framework that works with Selenium to manage test execution. Selenium is responsible for browser automation, while TestNG provides test organization, annotations, assertions, parallel execution, data-driven testing through DataProviders, grouping, reporting, and listener support. In automation frameworks, TestNG acts as the test runner and Selenium acts as the browser automation tool.
